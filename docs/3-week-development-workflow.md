# 3주 개발 진행 방식

이 문서는 레포를 실제로 개발할 때 따르는 작업 순서입니다. [`docs/curriculum-3-weeks.md`](curriculum-3-weeks.md)가 주차별 학습 항목이라면, 이 문서는 **무엇을 어떤 순서로 만들고 검증할지**를 정리한 개발 운영표입니다.

## 공통 원칙

- 매주 하나의 완성 가능한 목표를 둡니다.
- 기능을 크게 만들기보다 “작게 만들고 바로 검증”합니다.
- 실제 돈, 메인넷, 실거래, 금융 조언, 공식 제휴 표현은 어떤 주차에도 추가하지 않습니다.
- 새 기능은 먼저 기대 동작을 적고, 가능하면 테스트로 보호한 뒤 구현합니다.
- 각 주차 폴더의 항목을 끝낸 뒤 종료 기준을 확인합니다.

## 주차별 폴더 구조

```text
docs/
  week-1-foundation/        1주 차: 기초와 메커니즘
  week-2-market-flow/       2주 차: 제품 흐름
  week-3-polish-deploy/     3주 차: QA, 배포, 포트폴리오
```

| 주차 | 학습 폴더 | 개발 브랜치 예시 | 목적 |
| --- | --- | --- | --- |
| 1주 차 | [`week-1-foundation/`](week-1-foundation/) | `week-1-foundation` | 프로젝트 뼈대, 안전 경계, 도메인 모델 |
| 2주 차 | [`week-2-market-flow/`](week-2-market-flow/) | `week-2-market-flow` | 마켓 목록/상세, 거래, 포트폴리오, 정산 |
| 3주 차 | [`week-3-polish-deploy/`](week-3-polish-deploy/) | `week-3-polish-deploy` | 목업 지갑, 문서, 테스트, 배포, 포트폴리오 |

## 주차별 작업 루프

1. 해당 주차 폴더의 `README.md`를 엽니다.
2. 항목을 위에서부터 하나씩 진행합니다.
3. 항목마다 관련 파일을 읽고, 필요한 최소 수정만 합니다.
4. 주차별 검증 명령을 실행합니다.
5. 실패하면 첫 오류부터 고칩니다.
6. 주차 종료 기준을 만족하면 다음 주차 폴더로 이동합니다.

## 1주 차 — 기초와 메커니즘 만들기

자세한 항목: [`docs/week-1-foundation/`](week-1-foundation/)

목표: 앱이 실행되고, 안전 범위가 명확하며, 예측시장 장난감 모델을 테스트로 설명할 수 있게 만듭니다.

### 개발 범위

1. 프로젝트 실행 환경 준비
2. 안전 범위 이해
3. 마켓 데이터 구조 읽기
4. 마켓 엔진 이해 또는 구현
5. 단위 테스트로 메커니즘 보호

### 검증 명령

```bash
npm run lint
npm run test
```

### 종료 기준

- 앱이 `npm run dev`로 실행됩니다.
- `npm run lint`와 `npm run test`가 통과합니다.
- YES를 사면 YES 확률이 올라가는 이유를 설명할 수 있습니다.
- 이 레포가 실제 거래소가 아닌 이유를 README 또는 안전 문서에서 확인할 수 있습니다.

## 2주 차 — 사용자가 만지는 제품 흐름 만들기

자세한 항목: [`docs/week-2-market-flow/`](week-2-market-flow/)

목표: 학습자가 화면에서 마켓을 고르고, YES/NO를 선택하고, 포트폴리오와 확률 변화를 확인할 수 있게 만듭니다.

### 개발 범위

1. 홈 마켓 목록 구성
2. 마켓 카드와 상세 이동 이해
3. 마켓 상세 페이지 연결
4. 거래 패널 사용 흐름 구현/이해
5. 포트폴리오와 localStorage 상태 이해
6. 모의 정산 흐름 확인

### 검증 명령

```bash
npm run lint
npm run test
npm run build
```

### 종료 기준

- `npm run build`가 통과합니다.
- 마켓 보기 → YES/NO 선택 → 확률/포지션 업데이트 → 모의 정산 흐름을 완료할 수 있습니다.
- 상태 저장이 클라이언트 전용임을 설명할 수 있습니다.

## 3주 차 — 학습 완성도, QA, 배포 준비

자세한 항목: [`docs/week-3-polish-deploy/`](week-3-polish-deploy/)

목표: 안전한 목업 지갑과 문서를 정리하고, 자동 검증과 배포 준비까지 마쳐 포트폴리오로 설명할 수 있게 만듭니다.

### 개발 범위

1. 목업 지갑 실험 이해
2. 학습 콜아웃과 설명 문구 점검
3. E2E 테스트로 핵심 흐름 보호
4. 초보자 문서 정리
5. 배포 준비
6. 포트폴리오 설명 작성

### 검증 명령

```bash
npm run lint
npm run test
npm run build
npm run test:e2e
```

Playwright 브라우저가 없다면 한 번만 설치합니다.

```bash
npx playwright install chromium
```

### 종료 기준

- 모든 검증 명령이 통과하거나, 실패한 정확한 이유가 문서화됩니다.
- 목업 지갑이 실제 지갑, 시드 문구, 서명, 메인넷을 사용하지 않는다고 설명할 수 있습니다.
- 배포 URL 또는 배포를 막는 정확한 이유가 준비됩니다.
- 포트폴리오 설명에 안전 경계와 기술 선택 이유가 포함됩니다.

## AI 어시스턴트에게 요청할 때

```text
2주 차 폴더의 4번 항목인 거래 패널 사용 흐름만 진행하려고 해. 바꿔야 할 파일, 기대 동작, 실행할 테스트를 먼저 정리해줘. 실제 돈/메인넷/금융 조언은 추가하지 마.
```

```text

```
